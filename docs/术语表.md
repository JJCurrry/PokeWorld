# 术语表（Glossary · 共识层）

> 只收「望文生义会错」的词——与主流一致的词一律不收。相同的不写，不同的才写；越短越有用。
> 词条格式：术语 / 本项目含义 / 地雷（与主流默认的差异）/ 出处。

| 术语 | 本项目含义 | 地雷（与主流默认的差异） | 出处 |
|---|---|---|---|
| 区域 Region | 骨架层的固定节点：有名字、地标、解锁条件 | 不是「一整块可随机生成的地图」；区域本身手工定，只有内部由种子生成 | ADR-001 / 不变量 #2 |
| 区块 Chunk | 区域内部由 `rng(seed, region, coord)` 决定的 8×8 地形单元 | 不是无缝开放世界的流式加载分块；本项目明确不做无缝大地图；生成结果不入存档 | ADR-001 / `src/gen/chunk.py` |
| 骨架 / 血肉 / 门控 | 三层：手工拓扑 / 种子生成内容 / 能力解锁边 | 「门控」在此指玩法上的能力解锁，与下条「质量门」不是一回事 | ADR-001 |
| 质量门 Gate | 验证墙里的四道门（规则 / 编译 / 测试 / 数据可加载）+ 第 0 道前置自检；规则门现为 R0–R7 | 易与上条「门控」混淆；写文档时须写明「能力门」或「质量门」 | `docs/任务架构细分.md` / `tools/gate.py` |
| 能力门 Unlock | `topology.json` 边上的 `requires` 字段 | 不是代码里的 `if` 分支；见不变量 #3 | 不变量 #3 |
| 潮灵 Creature | 本项目原创生物的统称 | **禁用**「宝可梦 / Pokémon / 口袋妖怪 / 精灵宝可梦」指称本项目资产；这些词仅可出现在风险讨论中 | `docs/GDD-v0.md` 溯源表 |
| 图鉴 Atlas | 收集册，记录已发现潮灵及其出没条件 | 不是编号驱动的全收集清单；收集感来自「在哪抓」而非「抓到第几号」 | `docs/GDD-v0.md` 核心循环 |
| 世界种子 world_seed | 全局唯一随机源输入，存档必存 | 不是每个区块各有一个独立种子 | 不变量 #1 #6 |
| 黄金种子 golden seed | 专用于快照测试的固定 seed（8 case 存在 `tests/golden_seed.json`） | 不是玩家存档里的种子；改动生成器/快照须人逐次确认，R7 比对登记哈希，重建走 `tools/make_golden.py`；已执行**两次**人确认变更（2026-11-14 G1-v2、2026-11-15 G1-v3），每次都只覆盖当次 | 不变量 #5 / `tools/gate.py::check_golden_snapshot` |
| 作品名 PokeWorld | 工程仓库名与游戏内标题同名（门控裁定） | ⚠️ **名称不代表获得任何第三方 IP 授权**；素材、角色、音乐、数值表仍须全部原创 | GDD-v0 第 1、6、7 节 |
| 第 0 道门 Optimize Probe | 四道门之前的前置自检：在 `python -O` 子进程投毒，并直接验证 `-O` / `PYTHONOPTIMIZE` 两条拦截分支 | 不是第五道功能门；它只防「验证墙自己假绿」，不检查业务代码；与门内被 skip 的两个用例等价 | `tools/verify_all.py::OPTIMIZE_PROBE` |
| 撞墙三要素 | 规则门失败信息必须含「规则名 + `文件:行` + 修正建议」 | 只报规则名不算会说话的墙；由 `tests/test_gate_rules.py::assert_hit` 统一断言 | `tools/gate.py::violation` |
| 溯源登记 Provenance | 每个潮灵须按 `\| 潮灵 \`cNN\` 名称 \|` 在 GDD-v0 逐行登记且名称与数据表一致 | 不是「类别写一行原创」或在正文提及即可；R5 结构化解析，防止伪造 | 不变量 #7 / `tools/gate.py::check_provenance` |
| ASSUMPTION 占位 | 已入库字段的**来源标注**（值由 AI 占位产生） | 2026-11-14 人已裁定沿用，不再表示「未决」；但**仍不等于最终平衡定稿**，G2 采样后仍须人复核；R5b 机器核对标记与清单的对应 | `docs/待裁定项.md` |
| 遭遇相对权重 encounter_weights | G1-v3 起按「区块地形均值 × 时段权重 × `rarity`」产出的**未归一化相对量**，同 pool 内各物种值**不同**（稀有度差异） | **不是概率**：值落在 0~1 只是因子相乘的巧合；G2 须按 `wᵢ/Σw` 加权抽样消费；捕捉难度 `base_catch` **不参与遭遇**（人裁决 S-02 回归锁保留），只进捕捉公式；`rarity` 是与之正交的独立维度（A11 数值为占位） | `src/gen/chunk.py` / `docs/adr/ADR-002-战斗数值与出没稀有度建模.md` §3 |
| 快照口径 G1-v2 / G1-v3 | G1-v2 = 2026-11-14 人裁决 S-02 后重拍（`d18d1b85…`）；G1-v3 = 2026-11-15 人确认「稀有度差异」后重拍（`3ab574e4…`） | 两版**地形格逐格未变**，区别都在权重口径（是否含捕捉难度 / 是否乘 rarity）；再变更仍须人确认，R7 比对登记哈希 | `tools/make_golden.py` / `tools/gate.py::check_golden_snapshot` |
| 状态转移 step | G2 的 `step(state, action, rng) -> state'`，返回**新** frozen 状态 | `rng` 是**不可变上下文**不是随机流；传 `Stream` 会被拒绝；同参重跑必须逐字段一致 | `src/battle/engine.py` / 不变量 #4 |
| 规则凝固快照 Rules | 构造状态时把三张表一次性转成不可变 tuple 塞进状态 | 不是「每次去读表」；`step` 不碰磁盘；改原表不会影响已构造的状态 | `src/battle/rules.py` |
| 比例型伤害公式 | G2 返工（`ADR-002` §2）：`max(min_damage, round(power × 克制 × atk_scale / (1 + guard / guard_scale)))` | 结构常数**全部来自 `damage_formula` 表**，代码零硬编码；不再是减法型占位；实测 6–48、均值 18.4375、零触底组；数值仍是 A11 候选占位 | `src/battle/rules.py` / `docs/平衡采样报告.md` §6 |
| 出没稀有度 rarity | `species.json` 每个潮灵的固有出没系数（1.00 → 0.12），只乘进 G1 遭遇权重 | **不是捕捉难度**：与 `base_catch` 公式上不耦合，方向一致只是设计选择；改它不改地形格，但会改快照 → 须人确认（R7） | `docs/adr/ADR-002-战斗数值与出没稀有度建模.md` §3 |
| 道具 / 异常状态建模 | `item:<id>` 动作消耗背包道具；三档网给球倍率，两类状态道具按 `apply_rate` 施加状态；状态带 `duration` / `counter_rate` | `step(state, action, rng)` 签名**没变**，用动作字符串编码；`Creature.statused: bool` 已换成 `status` + `status_ticks`；全部 frozen、`replace` 返回新对象 | `src/battle/engine.py` / `state.py` |
| 满血钳制 S2-03 | 捕捉公式 hp 项仍是 `(1 - hp_ratio)`，满血时所有球 / 状态倍率被乘成 0 → 恒落下限 0.02 | **归人未裁决**：本轮三项建模已完成，但满血场景道具 / 状态全部失效；不是实现缺陷，是公式性质；是否改带基数 hp 项见 `ADR-002` §5 | `docs/平衡采样报告.md` §3 / `tests/test_battle.py` 回归锁 |

> 用法：写工单 / 计划时，凡涉及上表术语，显式点名相关词条，避免双向静默填空。
