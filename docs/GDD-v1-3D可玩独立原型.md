## 1. 一句话定位

玩家扮演潮屿巡游者，在**手绘风 3D 群岛**中自由行走，遭遇**看得见的野生潮灵**，用即时动作（攻击 / 闪避 / 捕捉）收服它们、填满图鉴，并用获得的能力门解锁新区域——单次游玩 20–30 分钟即可完成一条"探索→遭遇→捕捉→解锁"的完整体验。

## 2. 品类与对标

| 项 | 内容 |
|---|---|
| 品类 | 3D 动作捕捉 RPG（Action-Capture RPG） |
| 对标 1 | 《宝可梦 阿尔宙斯》——取"野外可见目标 + 主动接触触发战斗"的机制层，**不取**角色造型 / 地名 / 美术 |
| 对标 2 | 《A Short Hike》——取"小规模开放探索 + 低压力节奏 + 手绘氛围" |
| 差异点 | ① 种子派生的手绘群岛布局（骨架固定、细节生成）；② 捕捉成功率与失血 / 状态强耦合，鼓励"先战再抓"而非一击必中；③ 能力门来自图鉴进度而非单纯等级 |

## 3. 目标用户与场景

- 用户：自用为主，PC 单机玩家，喜欢收集 + 轻探索，不想被高强度数值碾压。
- 场景：晚间 20–30 分钟一段的休闲游玩；随时可停，存档恢复后世界一致。
- 单局时长：20–30 分钟（一个区域探索 + 2–4 次遭遇 + 1 个能力门节点）。

## 5. 核心循环（三层）

| 层级 | 环节 | 耗时 |
|---|---|---|
| 秒级（操作） | 移动 → 锁定目标 → 轻击/重击 → 闪避 → 捕捉 | 3–15 秒/次遭遇 |
| 分钟级（单局） | 探索区域 → 遭遇 2–4 只 → 图鉴登记 → 拿到能力 → 开门 | 20–30 分钟 |
| 小时级（成长） | 集齐区域图鉴 → 解锁下一区域 → 队伍成长 / 潮灵进化 → 终局 | 6–10 小时（待实测） |

## 6. 核心机制清单

| 编号 | 名称 | 作用 | 规则 | 玩家感知 |
|---|---|---|---|---|
| MECH-001 | 核心循环 | 串起三段体验 | 探索→可见遭遇→战斗/捕捉→图鉴→能力门→新区域 | 每 20 分钟有明确"下一个要去的地方" |
| MECH-002 | 战斗状态机 | 让操作有反馈 | Idle→Approach→Strike(前摇/命中/后摇)→Dodge(i-frame)→Capture→Result，唯一入口 `BattleSystem.Apply(action)`，状态不可变 | 按键后 1 帧内有动作，命中/受击有震动+音效 |
| MECH-003 | 主动接触遭遇 | 消除随机打断 | 野外潮灵可见，进入 8 m 警戒半径才进入战斗；离开 20 m 脱战 | 玩家自己决定何时开战，不再"走 5 步被强制打断" |
| MECH-004 | 能力门 | 让成长有意义 | 从图鉴条目数派生能力（游泳/攀岩/冲撞），门条件写在 `regions.json`，代码零能力名字面量 | 拿到新能力后明显看到"以前过不去的地方能过了" |
| MECH-005 | 图鉴登记 | 收集驱动 | 捕获或击败后登记（区域/地形/时段），条目数驱动 MECH-004 | 图鉴页有明确的空格与完成度百分比 |
| MECH-006 | 存档与确定性 | 随时可停 | 存种子 + flags + 队伍状态，世界由种子重建，不存生成结果 | 读档后地标位置、图鉴条目一致 |

## 7. 关卡与流程结构

| 区域 | 难度系数 | 类型 | 新增机制 | 设计意图 |
|---|---|---|---|---|
| 1 汐湾镇 | 1.0 | 教学 | 移动 / 轻击 / 捕捉 | 建立信心，第一次捕捉必成功（教学保底） |
| 2 青草原 | 1.0 | 教学 | 闪避 / 重击 | 巩固操作 |
| 3 回声洞 | 1.3 | 常规 | 碎岩能力门 | 引入能力解锁 |
| 4 灯塔港 | 1.3 | 常规 | 时段差异（夜潮） | 引入时段收集 |
| 5 碎浪群 | 2.2 | 挑战 | 冲浪能力门 + 复合遭遇 | 检验掌握 |
| 6 灰火岛 | 0.9 | 喘息 | 无新机制 | 节奏回落 |
| 7 联盟 | 2.6 | 终局 | 队伍战 | 收束 |

难度系数来源（可计算）：`系数 = 区域潮灵平均(攻击×生命) × 同屏数量 ÷ 玩家该阶段期望输出`，取整到 0.1。**无连续 3 关单调上升**（1.0→1.0→1.3→1.3→2.2→0.9→2.6，第 6 关为喘息）。

## 8. 数值与成长框架

### 8.1 成长曲线（3 锚点 + 分段插值）

| 锚点 | 等级 | 主属性倍率 |
|---|---|---|
| 起点 | 1 | 1.0× |
| 中点 | 10 | 3.0× |
| 终点 | 20 | 6.0× |

增长率：1–5 级每级 +25%，6–20 级每级 +12%（复利近似：1.25⁵≈3.05，故中点取 3.0；1.25⁵×1.12¹⁵≈16.7，超出 6.0 → 采用**分段线性插值**而非复利：1→10 每级 +0.222，10→20 每级 +0.3，端点严格过锚点）。【待实测】

### 8.2 伤害公式（定义域 + 极值验算）

```
dmg = max(1, round((base × lvRatio + pool) × typeMulti × (1 - min(defense/(defense+K), 0.7))))
```

| 项 | 含义 | 取值范围 | 单位 |
|---|---|---|---|
| base | 招式基础值（轻击 12 / 重击 30） | 12–30 | 点 |
| lvRatio | 成长倍率 | 0.5–4.0 | 倍 |
| pool | 附加池 | 0–20 | 点 |
| typeMulti | 属性克制 | 0.5 / 1.0 / 2.0 | 倍 |
| defense | 目标防御 | 0–60 | 点 |
| K | 减伤常数 | 60 | 点 |

极值验算：
- 全最小：`(12×0.5+0)×0.5×(1−0/60)=3.0` → round 3 → `max(1,3)=3`（不为负）
- 全最大：`(30×4+20)×2.0×(1−0)=280`（在 60 点上_limit 的 4.7 倍，需 boss 生命 ≥ 600 才不被一击秒，见 §7 终局）
- 边界扣除：`defense=60,K=60 → 60/120=0.5 < 0.7` 钳制未触发；`defense→∞` 时比值钳到 0.7，保留 30% 伤害，**不会归零**

### 8.3 捕捉公式（定义域 + 极值验算）

```
p = clamp(catchBase × (0.15 + 0.85 × (1 - hp/maxHp)) × ballBonus × statusBonus, 0.02, 0.95)
```

| 项 | 含义 | 取值范围 |
|---|---|---|
| catchBase | 物种基础捕捉率 | 0.08–0.32 |
| hp/maxHp | 当前血量比 | 0–1 |
| ballBonus | 捕捉网倍率 | 1.0 / 1.4 / 1.8 |
| statusBonus | 状态倍率 | 1.0 / 1.5 / 1.8 |

极值验算：
- 全最小（满血、普通网、无状态、最低 species）：`0.08×0.15×1×1=0.012` → 钳到 **0.02**
- 全最大（残血、高级网+状态、最高 species）：`0.32×1.0×1.8×1.8=1.0368` → 钳到 **0.95**
- 设计意图：**满血几乎抓不到，先打到残血再抓**，鼓励战斗而非一击必中。

### 8.4 经济三件套

| 项 | 内容 |
|---|---|
| 产出 | 每场战斗掉潮汐碎片 2–5（期望 3.5）；每个地标巡查 +10 |
| 消耗 | 捕捉网 5 碎片/个；治疗 3 碎片/次 |
| 存量 | 上限 999，软上限 500（超出提示"背包已满"），无溢出丢失 |

单局（10 分钟）校验：产出 `4×3.5+10=24`；消耗 `3×5+1×3=18`；比值 `24/18≈1.33`，落在目标区间 **1.1–1.4**。【待实测】

### 8.5 掉率与期望

| 物品 | 单次概率 | 保底 | 期望次数 |
|---|---|---|---|
| 潮汐碎片（普通） | 40% | 无 | 1/0.4=2.5 次 |
| 稀有潮灵 | 3% | 10 次必出 | ≈6.6 次 |
| 限定潮灵 | 0.5% | 80 次必出 | ≈55 次 |

时间成本换算：稀有潮灵 `6.6×3.5 碎片/场 ≈ 23 碎片`，按单局产出 24 碎片 → 约 1 局可攒够；限定约 8–9 局。【待实测】

## 10. 音频与表现

- 音效清单：脚步、轻击命中、重击命中、受击、闪避、捕捉成功/失败、图鉴登记、能力解锁、UI 确认，各 1 个（`sfx_*`）。
- 音乐切换：探索 BGM → 进入战斗淡出 0.5s → 战斗 BGM → 结算淡入 0.5s 回探索；时段 night 用同一曲的低通变体。
- 打击感反馈点：命中帧暂停 0.06s（hit-stop）+ 屏幕轻震 2px + 白色闪帧 1 帧 + 伤害飘字。

## 11. UI / UX 与信息架构

界面清单与跳转：启动 → 主菜单（新游戏/继续）→ 游戏 HUD（血量/碎片/目标/小地图）→ Tab 图鉴 → 战斗 HUD（招式/捕捉/道具）→ 结算 → 回 HUD；Esc 暂停 → 设置 / 回主菜单。
首启流程：区域 1 开场 → 3 步移动教学 → 1 次必成功捕捉教学 → 自由探索。**关键元素不进入 §4 安全区**。

## 12. 技术方案与工程结构

- 引擎：Unity（版本【假设 H2】待核验，以用户本机 / Hub 新建工程为准，不臆造）。
- 目录：`Assets/{Scripts,Scripts/Editor,Art,Audio,Prefabs,Scenes,Settings}`；场景由 Editor 脚本生成并写入构建列表，**不手写场景 YAML**。
- 数据：`Assets/Settings/Regions.json` / `Creatures.json` 等 JSON 配置，运行时只读加载；代码零能力名字面量（沿用旧工程 R3 精神）。
- 程序集：`PokeWorld.Core`（状态机/规则）、`PokeWorld.View`（表现/输入），View 只读 Core 投影。
- 引用标记：每个实现文件写 `// @trace 编号`，冻结清单统计覆盖率。
