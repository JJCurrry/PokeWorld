# ADR-005：可玩闭环的分层（表现层只读）与可选依赖 pygame

> 意图层记忆：为什么这样设计。结构 AI 读代码能重建，意图只能靠人沉淀。
> 一页纸：背景 / 决定 / 被否决的备选及原因 / 后果。
> 状态：**G5 设计定稿（2026-11-16，人授权开工后）**；实施结论与逐条机器证据以 `docs/工单/G5-可玩闭环.md` 的实测为准。

## 背景（Context）

`docs/任务架构细分.md` §1 给 G5 的 DoD 是两条：「从起始区域走到联盟可完整通关；依赖缺失时验证墙优雅跳过」，范围「引入 pygame（首个第三方依赖），2D 俯视渲染 / 输入 / 存档」，委托级别「中委托 / **B 级**（手感与观感需人裁决）」。§3 同时定下两条硬约束：「表现层只读状态，不回写世界；世界状态唯一入口是纯函数状态转移」「G5 才引入 pygame；CI 中依赖缺失须优雅跳过、不破管」。

2026-11-16 人答复「**G4验收通过，开启G5的开发工作**」授权开工，但延续 G3 / G4 的制度性边界：**本次授权不含改受保护三表 / 重建 `MANIFEST.sha256` / 重拍 `tests/golden_seed.json` 的逐次确认**（见 G4 工单「人裁决记录（第二次）」）。于是 G5 面对一组叠加约束：

- 不变量 #2：三张 `data/*.json` 是唯一事实源、AI 只读；不新增第四张表。UI 文案 / 键位 / 配色不能「顺手」写进表。
- 不变量 #3 / R3a：`topology.json` 的四个能力名在代码中**零出现**（连字符串常量拼接 / f-string 常量段都折叠检查）；R3b 拦 `has` / `require` / `unlock` / `can_enter` 类调用。通关判定不得写死 `r7` 或能力名。
- 不变量 #1 / R1：随机与时钟不参与生成；`random` / `numpy` / `time` / `secrets` / `datetime` 及其属性调用在生产代码里被规则门拦。渲染节流若用帧钟，必须严格限定在表现层、不进入任何世界状态。
- 不变量 #6：存档只存 `world_seed + flags + 队伍状态`；区块生成结果禁止入库，必须由 seed 重建。
- `docs/地图.md`：数据流单向 —— 骨架表 → 生成器 → 区块 → 遭遇 / 战斗纯函数 → 状态；**表现层只读状态，不回写世界**。
- G4 已确立：`progress.step` 是跨区域移动的唯一入口，`game.apply_effects` 是脚本效果转状态的唯一入口，`game.train` 是成长通道。G5 不得开第二入口。
- R5 / `docs/GDD-v0.md` §6：新增资产（界面文案 / 地形色块 / 字体 / 代码依赖）须先登记溯源表；人已裁定「自己玩无所谓」→ 自用不上架、不做商标检索与近似风险评估，AI 不作法律判断。

环境实测（2026-11-16）：本机 pygame 2.6.1（SDL 2.28.4）可用，`SDL_VIDEODRIVER=dummy` 下能创建 Surface / 绘图 / flip；`autoplayer` 确定性巡图 20 步终点即联盟、`blocked=0`。**但不能因本机已装就把 pygame 写成硬依赖** —— DoD 明确要求缺失时验证墙优雅跳过。

## 决定（Decision）

1. **三层分离，表现层只读**。`src/world/session.py` 是会话层（frozen `Session`，聚合 G4 `GameState` 与视图游标 / 时段 / 消息），`apply(session, action, tables) -> Session` 是**唯一**把输入变成状态的纯函数：世界推进只调用既有 `progress.step`，图鉴登记走 `game.observe` / `atlas.observe_chunk`，脚本效果走 `game.apply_effects`，成长走 `game.train`。`src/view/layout.py::frame_of` 把 `Session` **投影**成 frozen `Frame`（地形色块 + 文本行），不持有可变引用、不改任何输入；`src/view/window.py` 只按 `Frame` 画并把按键翻译成动作字符串。**渲染层拿不到状态写入口**，因此「表现层只读」既是结构事实，也可用行为 + AST 双重证明。

2. **通关终点由拓扑派生，不写死作者意图**。`goal_region(world)` 返回**唯一没有出边的区域**（当前链式拓扑即联盟）；有多于一个或无出边时显式抛错。动作序列复用 `autoplayer.choose_action`（表序确定性、零随机），每一步用 `edge_is_open` 校验 `requires ⊆ abilities`，保证无跳关；`complete` 要求到达终点 + 全区域 / 全 NPC / 全区块巡查 + 图鉴里程碑达成，并用死端拓扑表副本反证为 False（与 G3 / G4 的反证同构）。区域名、地标、解锁顺序仍归人（原则 6），本决定不替人决定任何骨架字段。

3. **pygame 是可选依赖，顶层零 import**。`src/view/deps.py::pygame_available()` 用 `importlib.util.find_spec` 探测，不执行导入；`POKEWORLD_NO_PYGAME=1` 提供**可复现的缺失模拟**，用于在没有卸载 pygame 的机器上实测缺失分支。`src/view/window.py` 只在真正开窗口的函数内延迟 `import pygame`，并捕获 `ImportError` 转成带安装提示的 `ViewUnavailable`；`src/main.py` 顶层同样零 pygame import，缺失时 `--window` 打印明确提示并降级到 headless 通关（exit 0）。因此：
   - 第 2 门 `compileall` 只编译不 import → 缺依赖不破管；
   - 第 3 门 `unittest` 用 `@unittest.skipUnless(pygame_available(), ...)` → 视图用例显式 skip、其余用例照常；
   - 第 1 门规则门是纯 AST 静态检查、第 4 门只加载三张表 → 都不碰 pygame。
   - 缺失分支的证据由 `tools/g5_report.py` 与 `tests/test_g5_dependency.py` 在**真实子进程**里给出（模拟缺失跑完整 `verify_all.py`，核对 `ALL GATES GREEN` 与 `skipped=N`），不是注释自称。

4. **存档沿用 G4 投影，文件 I/O 只在入口层**。`to_save` → `encode` 产出确定性的三类字段字符串，`src/main.py` 的 `--save` / `--load` 才读写 `saves/`（已被 `.gitignore` 排除，存档不入库）；`decode` → `from_save` 还原后必须能**继续推进到联盟**，作为「存档不破坏可通关性」的机器证据。生成结果仍由 `world_seed` 重建，不进存档（不变量 #6）。G4 已知限制 S4-02（读档不还原图鉴地形 / 时段条件）原样保留，不借 G5 偷偷扩大存档字段。

5. **零改表 / 零重建清单 / 零重拍快照**。UI 文案、键位、配色是**代码内的纯字面量常量**（受 R0–R7 扫描，不形成盲区），不写入三张表、不新增第四张表；不改生成器 / 三表 / 伤害 / 捕捉公式，按 G3 先例 S3-04 无需重跑 `balance_check.py`；R7 哈希保持 G1-v3。新增 `requirements.txt` 只声明可选依赖，不改变「验证墙零依赖可跑」的性质。

## 被否决的备选及原因（Alternatives considered）

- **让渲染层直接持有并修改 `GameState` / `Progress`** —— 否决：破坏 `docs/地图.md` 的单向数据流与「表现层只读」，会开出第二个状态入口，G3 的无跳关证明与 G4 的「脚本不改世界状态」证明同时失效。
- **顶层 `import pygame`，测试里靠 try/except 兜住** —— 否决：`unittest discover` 会在收集阶段 import 测试模块，缺依赖时第 3 门直接崩，不满足「验证墙优雅跳过」；改为函数内延迟导入 + `find_spec` 探测。
- **改 `verify_all.py` 在缺依赖时跳过整个测试门** —— 否决：那是把墙变哑来「修绿」，违反 `CLAUDE.md` 原则 4；改为只跳过**需要 pygame 的那几个用例**，其余门禁照常全跑。
- **把 UI 文案 / 键位 / 配色写进 `encounters.json` 或新增第四张表** —— 否决：违反不变量 #2，且本次授权不含改表逐次确认；`ADR-003` / `ADR-004` 已就同类问题否决过。
- **把通关终点写成 `r7`、把门控能力名写成常量** —— 否决：既撞 R3a（能力名零出现）/ R3b，又把「区域命名 / 解锁顺序」这类作者意图据为己有（原则 6）；改为从 `World.edges` 派生无出边终点、能力集合从表读。
- **用 `random` / `time` 做动画抖动或帧钟驱动世界** —— 否决：撞 R1 与不变量 #1，且会让同种子重放不一致；渲染节流只允许用不进入世界状态的帧钟，本实现干脆用事件驱动 + `display.flip()`，不读时钟。
- **G5 顺带补战斗 / 捕捉 UI、进化造型、打包发布** —— 否决：超出 §1 G5 行范围，B 级手感观感尚未由人裁定，先扩大面积会让返工成本不可控；留 G6 或另开工单。
- **重跑 `balance_check.py` / 重拍 golden 快照** —— 否决：G5 不改生成器、三表、伤害 / 捕捉公式，采样输入集合未变；快照变更须人逐次确认，本次授权未含。

## 后果（Consequences）

- 正面：首次把 G1–G4 的能力串成**可玩闭环**（输入 → 状态 → 渲染 → 存档），且闭环的证据完全由 headless 纯函数给出，不依赖显示器；pygame 缺失时四道门仍可全绿，验证墙不因首个第三方依赖破管；全程零改表 / 零重建 MANIFEST / 零重拍快照。
- 负面 / 已知限制：**B 级手感与观感（键位、配色、窗口尺寸、中文显示）机器只能证明「能画、能走、能存」，不能证明好玩或好看**，须人试玩裁定；中文渲染依赖本机系统字体，无内置第三方字体（已在 GDD §6 登记为待补 / 已知限制）；pygame 的许可证义务仅按官方声明登记为「待核」，**AI 不作法律判断**，人已裁定自用不上架；新增 UI 文案是 AI 草案，与 G4 的 16 条脚本一样属 B 级品味归人复核。
- 边界：本决定不新增、不改写当前 `docs/接力文件.md`「待人类裁决的问题」的任何裁决项（当前 1 项 = G4 的 B 级文案品味）。G3 的 S3-01 / S3-02、G4 的 S4-01 / S4-02 / S4-03 / S4-05 继续如实登记；G5 的通关证据只覆盖当前链式拓扑，不把结论外推到分叉 / 环路。
- G5 交付时按 A9 产生新的里程碑裁决项（G5 是否验收通过 / 是否开工 G6 / B 级手感观感），AI 不提前预支、不自判通过。
