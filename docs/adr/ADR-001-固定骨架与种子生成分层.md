# ADR-001：固定骨架与种子生成分层

> 意图层记忆：为什么这样设计。结构 AI 读代码能重建，意图只能靠人沉淀。
> 一页纸：背景 / 决定 / 被否决的备选及原因 / 后果。

## 背景（Context）

项目想要同时具备两种体验：① 程序化群岛带来的「每局地形都不同、可无限扩张」；② 经典回合制大地图带来的「有地标、有顺序、我记得那个洞窟后面有什么」。

这两者对「世界」的假设冲突：纯生成世界没有「该去哪」，玩家跑二十分钟后记不住任何地方，图鉴退化成刷数字；纯手工复刻则内容量爆炸，AI 在事件脚本破百条后开始互相改坏。

同时本项目以 AI Coding 为主要开发方式，需要一个**边界清晰、可机器校验**的结构，让 AI 只在可测区域自由发挥。

## 决定（Decision）

世界分三层，作者权与生成权严格分离：

- **A 骨架层（人工定 · 受保护）**：区域拓扑、地标、剧情事件、图鉴里程碑、能力门条件，全部落在 `data/topology.json` 等三张表；AI 只读。
- **B 血肉层（种子生成 · 纯函数）**：区块地形、遭遇权重、道具与隐藏点，由 `rng(world_seed, region_id, cx, cy)` 决定；golden seed 快照锁定。
- **C 门控层（表驱动）**：能力门只在 `topology.json` 的 `edges[].requires` 声明，代码里禁止硬编码；把生成内容挂到玩家进度上，让「新区域」因为「玩家变强」而有意义。

配套：所有规则尽量下沉为 `tools/gate.py` 的静态检查（会说话的墙），而非文档里的劝告。

## 被否决的备选及原因（Alternatives considered）

- **纯程序化无限群岛** —— 否决原因：无地标、无进度记忆，探索动机衰减快；且玩家无法形成「我终于到了」的成就感。
- **纯手工大地图复刻** —— 否决原因：内容量线性膨胀，事件脚本破百后 AI 互相改坏；失去程序化生成这一 AI Coding 最擅长的部分。
- **无缝连续大地图 / 流式加载** —— 否决原因：区块边界与状态边界耦合，存档、测试、确定性都变复杂，是 AI 最容易写崩的形态；改用「分区块 + 明确传送门」。
- **把门控写成代码里的 `if has("surf")`** —— 否决原因：进度锁散落后改一处漏一处，出现跳关或卡死；改为表驱动。
- **3D 实时世界** —— 否决原因：镜头、碰撞、动画状态机依赖美术与手感调试，是 AI Coding 弱项；本项目定位 2D 俯视规则密集。

## 后果（Consequences）

- 正面：边界清晰 → 架构测试可自动校验「AI 有没有跨层」；生成器纯函数 → 可快照、可大规模采样；骨架表受保护 → 作者意图不被模式放大器稀释。
- 负面：世界「无限性」被限制在区域内部，全局区域数由人定；门控表需要人持续维护，新增区域必须显式声明解锁条件。
- 后续注意：改动生成器导致 golden seed 快照变化时，**必须人确认**，禁止 AI 顺手更新快照把测试「修绿」（见不变量 #5）。
