## 1. 背景与要解决的问题

| # | 现状（G2 已实现） | 问题（实测） |
|---|---|---|
| G2-01 | `damage = max(1, int(power × 克制倍率) − guard // 2)`，结构常数硬编码在 `src/battle/rules.py` | 8×8 矩阵范围 **1–124**、均值 36.4，**4 组保底 1 点、7 组 ≤3 点**；粗估 1.4 回合结束战斗。减法型公式让 0.5 倍克制 + 高守组合「几乎打不动」，结构常数又不在表里（违反「因子来自表」的既有口径） |

## 2. 决策一：伤害公式改写（G2-01）

**改为比例型公式，全部结构常数入表**，替换减法型：

```
dmg = max(min_damage, round(power × multiplier × atk_scale / (1 + guard / guard_scale)))
```

- `multiplier` 仍只取 `encounters.json::type_chart`，代码零硬编码（不变量 #3）。
- 新增 `encounters.json::damage_formula`：`{"atk_scale": 0.55, "guard_scale": 60, "min_damage": 3}`。
- 用「除以防御因子」而非「减去防御」，克制倍率不再被减法压成 1 点；`guard_scale = 60` 取现有 guard 的中位量级，使 60 防约等于伤害减半。

**只读测算（8×8 = 64 组，未改任何文件）**：

| 指标 | 旧（AI 占位） | 新（推荐 0.55） |
|---|---|---|
| 范围 | 1 – 124 | **6 – 48** |
| 均值 / 中位数 | 36.4 / 30 | **18.4 / 15** |
| 保底 / ≤3 点组数 | 4 / 7 | **0 / 0** |
| 粗估平均回合数（HP 44–70 ÷ 均值） | 1.4 | **2.9** |

系数敏感度（`guard_scale=60`、`min_damage=3`）：`0.50 → 5–43 / 均值 16.8 / 3.1 回合`、`0.55 → 6–48 / 18.4 / 2.9`、`0.60 → 6–52 / 20.1 / 2.6`、`0.70 → 7–60 / 23.5 / 2.2`。选 **0.55** 的理由：回合数落在收集类回合制常见的 3 回合量级，同时保留克制倍率的可感知差异（最低 6、最高 48，8 倍跨度而非 124 倍）。

## 3. 决策二：出没稀有度差异化（G2-02）

**在 `species.json` 每个潮灵新增 `rarity`（物种固有的出没系数）**，`generate_chunk` 权重改为：

```
w(cid) = phase_weight × terrain_mean × rarity[cid]
```

- **扩展而非推翻人裁决 S-02**：`region_pool` 仍是候选集合；`base_catch` **仍不参与遭遇权重**（拆通道口径保持）。新增的 `rarity` 是与捕捉难度正交的独立维度，由人分别定稿。
- 取值设计原则：越靠后的区域、越难捕捉的潮灵出没系数越低；系数与 `base_catch` 方向一致，但**公式上不耦合**。

| 潮灵 | c01 | c02 | c03 | c04 | c05 | c06 | c07 | c08 |
|---|---|---|---|---|---|---|---|---|
| `rarity` | 1.00 | 0.62 | 0.75 | 0.55 | 0.34 | 0.28 | 0.30 | 0.12 |
| `base_catch`（对照，不进权重） | 0.42 | 0.34 | 0.40 | 0.36 | 0.30 | 0.28 | 0.32 | 0.16 |

**只读测算：各区域 day 遭遇比例**（地形均值沿用报告里的 0.7625）：

| 区域 | pool | 遭遇比例 | day 相对权重 |
|---|---|---|---|
| r1 汐湾镇 | c01 / c02 | 61.7% / 38.3% | 0.7625 / 0.4727 |
| r2 青草原 | c01 / c03 | 57.1% / 42.9% | 0.7625 / 0.5719 |
| r3 回声洞 | c04 / c05 | 61.8% / 38.2% | 0.4194 / 0.2592 |
| r4 灯塔港 | c02 / c06 | 68.9% / 31.1% | 0.4727 / 0.2135 |
| r5 碎浪群 | c02 / c07 | 67.4% / 32.6% | 0.4727 / 0.2287 |
| r6 灰火岛 | c05 / c08 | 73.9% / 26.1% | 0.2592 / 0.0915 |
| r7 联盟 | 空 | 无遭遇 | — |

差异化明显且不极端（最稀有的 c08 仍约 1/4 次遭遇），原型级不需要「刷几十次才见一面」的挫败感。物种级时段 / 地形偏好（GDD §2「出没条件驱动图鉴」）留 G4，本轮不做，避免过度工程化。

## 4. 决策三：道具与异常状态建模（G2-03）

**表驱动 + 纯函数；不改 `step(state, action, rng)` 签名**，用动作字符串编码新动作，保持现有 92 用例的调用方式可用。

### 4.1 新增表结构（`encounters.json`）

```json
"items": {
  "net_plain": {"name": "素织网", "kind": "ball",   "catch_bonus": 1.00},
  "net_fine":  {"name": "密织网", "kind": "ball",   "catch_bonus": 1.35},
  "net_tide":  {"name": "潮汐网", "kind": "ball",   "catch_bonus": 1.70},
  "bell_calm": {"name": "静息铃", "kind": "status", "status": "drowse", "apply_rate": 0.75},
  "seal_frost":{"name": "凝霜符", "kind": "status", "status": "numb",   "apply_rate": 0.60}
},
"statuses": {
  "drowse": {"name": "昏沉", "catch_bonus": 1.5, "duration": 3, "counter_rate": 0.5},
  "numb":   {"name": "僵麻", "catch_bonus": 1.8, "duration": 2, "counter_rate": 0.0}
}
```

- `catch_formula` 里的单值 `ball_bonus` / `status_bonus` 退场，改由道具 / 状态条目提供倍率；`min` / `max` 保留。
- `flee` 增加 `flee_base_rate`（如 0.75），按敏捷与状态判定，不再恒成功；仍用 `RngContext.stream("flee")` 消费，保持可复现。

### 4.2 状态与动作

| 动作 | 语义 |
|---|---|
| `"item:<id>"` | 消耗一件道具：ball 类设为「本次捕捉使用的网」；status 类按 `apply_rate` 由 rng 判定施加状态并置 `status_ticks = duration` |
| `"catch"` | 用当前装备的网计算 `p`，命中则 `caught`，未命中按状态的 `counter_rate` 决定是否反击 |
| `"attack"` / `"flee"` | 保持；每次动作后 `status_ticks` 递减，归零清除状态 |
| `"encounter"` | 保持；新出现的野生潮灵初始无状态 |

`BattleState` 增 `bag`（frozen tuple）与 `equipped_ball`；`Creature` 的 `statused: bool` 换成 `status: str | None` + `status_ticks: int`。全部用 `dataclasses.replace` 返回新对象，不违反不变量 #4；模块级仍只放不可变常量，校验一律 `schema.must()` / 显式 `ValueError`，不用 `assert`。

### 4.3 只读测算：道具与状态对捕捉率的影响

`p = clamp(base_catch × (1 − hp_ratio) × 球倍率 × 状态倍率, 0.02, 0.95)`

| 潮灵 | hp_ratio | 素织网 / 无 | 密织网 / 昏沉 | 潮汐网 / 僵麻 |
|---|---|---|---|---|
| c01 | 0.5 | 0.210 | 0.425 | 0.643 |
| c01 | 0.1 | 0.378 | 0.765 | 0.950 |
| c08 | 0.5 | 0.080 | 0.162 | 0.245 |
| c08 | 0.1 | 0.144 | 0.292 | 0.441 |

**原创合规**：道具 / 状态全部原创中文命名（素织网、密织网、潮汐网、静息铃、凝霜符、昏沉、僵麻），已用 `tools/gate.py::normalize` 对 `BANNED_WORDS` 做归一化自检，**零命中**；不使用任何第三方 IP 的道具名、状态名或角色名（R4 / 不变量 #7）。新资产入库前须在 `docs/GDD-v0.md` 第 6 节溯源表补登记。

## 5. 配套方案（S2-03 满血捕捉率）——**2026-11-15 22:02 人裁决「采纳」，已实施**

上表刻意没列 `hp_ratio = 1.0`：实测**无论换什么网、上什么状态，满血捕捉率恒为 0.020**，因为 `(1 − hp_ratio) = 0` 会把所有倍率乘成 0，再被 `min` 抬到下限。**若不处理 #5，本轮建模的道具与状态在满血场景全部失效，等于做了一半。**

建议把 hp 项改为带基数的线性项（不改上下限、不改 `base_catch`）：

```
hp_factor = catch_base + (1 - hp_ratio) × hp_weight     # catch_base=0.12, hp_weight=0.88
```

只读测算（`catch_base=0.12`）：

| 潮灵 | hp_ratio | hp 因子 | 素织网 / 无 | 潮汐网 / 僵麻 | 旧公式 |
|---|---|---|---|---|---|
| c01 | 1.0 | 0.120 | **0.050** | **0.154** | 0.020 |
| c01 | 0.5 | 0.560 | 0.235 | 0.720 | 0.210 |
| c01 | 0.1 | 0.912 | 0.383 | 0.950 | 0.378 |
| c08 | 1.0 | 0.120 | 0.020 | 0.059 | 0.020 |

半血 / 残血曲线几乎不变（误差 ≤0.025），满血从「恒 0.02」变成「有小概率、且道具与状态能拉开差距」。

**实施结果（2026-11-15 22:02 人裁决「采纳」后）**：两个常数入 `encounters.json::catch_formula`（`catch_base = 0.12` / `hp_weight = 0.88`），`Rules` / `catch_probability` / `schema.validate_encounters` 同步；`MANIFEST.sha256` 按人逐次确认重建（LF），`encounters.json` 哈希 `5ddb5bc9… → 55237782…`，另两张表未变；**未重拍 golden 快照**（生成器与 `species.json` 未变，`catch_formula` 不进入 `generate_chunk`，R7 仍 `3ab574e4…`）。重跑采样实测满血 c01 素织网 `0.050400` → 潮汐网+僵麻 `0.154224`（**3.06 倍**），与本节只读测算一致；40 组合最大误差 `0.0204`，详见 §8 与 `docs/平衡采样报告.md` §2 / §3。旧「满血恒落下限」回归锁已随人裁决撤销，改为「hp 基数生效 + 满血倍率可拉开差距」。
