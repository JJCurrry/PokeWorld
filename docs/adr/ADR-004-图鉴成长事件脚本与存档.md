# ADR-004：图鉴 / 成长进化 / 事件脚本 / 存档的零改表实现

> 意图层记忆：为什么这样设计。结构 AI 读代码能重建，意图只能靠人沉淀。
> 一页纸：背景 / 决定 / 被否决的备选及原因 / 后果。
> 状态：**G4 设计定稿（2026-11-16，人授权开工后）**。实施结论以 `docs/工单/G4-图鉴进化事件脚本.md` 的实测为准。

## 背景（Context）

`docs/任务架构细分.md` §1 给 G4 的 DoD 是三条：「图鉴里程碑可达成；存档 roundtrip 绿；事件脚本不直接改世界状态」，范围「收集册 / 成长 / ≤20 条事件脚本」（A8），委托级别「A 级 + B 级（文案品味）」。

2026-11-16 人答复「**开启下一步G4的开发**」授权开工，但延续 G3 的制度性边界：**本次授权不含改受保护三表 / 重建 `MANIFEST.sha256` / 重拍 `tests/golden_seed.json` 的逐次确认**（见 `docs/工单/G3-能力门与巡图.md`「人裁决记录（第二次）」）。于是 G4 面对一组叠加约束：

- 不变量 #2：三张 `data/*.json` 是唯一事实源、AI 只读；不新增第四张表（`ADR-003` 已否决同类）。
- 不变量 #3 / R3a：`topology.json` 的四个能力名在代码中**零出现**（连字符串常量拼接 / f-string 常量段都折叠检查）；R3b 拦 `has/require/unlock/can_enter` 类调用。
- 不变量 #1：所有随机只来自 `rng(world_seed, region_id, cx, cy)`；个体值也须由 seed 派生（GDD-v0 §4）。
- 不变量 #6：存档只存 `world_seed + flags + 队伍状态`；**区块生成结果禁止入库**，必须可由 seed 重建。该条的证据符号当时还是「未来符号 `tests/test_save_roundtrip.py`（当前不存在）」。
- GDD-v0 §2 / 术语表「图鉴 Atlas」：收集感来自**出没条件**（地形 / 时段 / 能力门），不是编号递增；图鉴里程碑按区域划分。
- R5 / `docs/GDD-v0.md` §6：新增资产须先登记溯源表；B 级文案品味归人复核。

人同次确认两项实施口径：① 成长 / 进化参数用**代码常量 + 本 ADR 登记**（不是表驱动）；② 事件脚本文案由 AI 出原创草案、**B 级品味归人复核**。

## 决定（Decision）

1. **图鉴按「出没条件」登记，里程碑由确定性巡图达成**。`AtlasEntry = (cid, region, terrain, phase)` 记录「在哪、什么地形、什么时段遇到」，不是第几号；`Atlas` 是 frozen，登记用 `dataclasses.replace` 返回新对象。里程碑按区域定义：每个有 `pool` 的区域，其 pool 中全部物种都在本区域被登记过才算达成；全部区域达成即 `complete=True`。证据链复用 G3 的巡图（`World` / `step` / 表序决策）：每巡查一个区块，调用既有 `generate_chunk` 取出 `terrain_counts` 主导地形与 `encounter_weights` 的各时段键，**按权重 > 0 的 cid 确定性登记**，不引入随机抽样。另用「死端拓扑表副本」反证 `complete` 不是恒真（与 G3 的 `complete` 反证同构）。r7 的 `pool` 为空 → 该区域里程碑平凡达成，在报告中如实标注，不冒充覆盖。

2. **成长 = 等级线性 + 由 seed 派生的个体修正；进化 = 同一潮灵的形态阶段，不新增物种**。
   - 成长刻度（`max_level` / `per_level` / `iv_span` / `evolve_levels`）集中在 `src/world/evolution.py` 的**单一模块级不可变常量**，本 ADR 明确登记它们是 **G4 实现约定，不是 A11 平衡数值**；A11 只覆盖三张表既有字段，本决定不改写 A11 定稿口径、不触碰 `balance_check.py` 与 `docs/平衡采样报告.md`。
   - 个体值由 `rng(world_seed, cid, 0, 0, stream="growth")` 派生：`rng` 的 `stream` 参数本就是为「同一四元组下隔离不同用途」设计的（`src/gen/rng.py`），生成区块用默认 `stream="chunk"`，两者互不干扰，**因此不触发 R7 快照变化**。
   - 进化只推进 `stage`（0/1/2）并重算数值，不产生新的生物 id、不新增造型资产 → 不扩大 R5 溯源表的 8 个潮灵条目。未来若要「进化成新物种」，须另开裁决 + 逐次确认改表 + 新 ADR。

3. **事件脚本是纯字面量数据，只产出「效果声明」，绝不直接改世界状态**。脚本定义 `SCRIPT_ROWS` 是模块级 tuple-of-tuples（字符串与 tuple，零可执行代码），≤20 条；由 `scripts.py` 转成 frozen `Script` / `Effect`。`select(context)` 与 `effects_of(...)` 是纯函数，返回 `tuple[Effect, ...]` 这类**意图声明**；`src/world/scripts.py` **不 import** `progress` / `game` / `save`，不含 `step(` / `replace(` / 任何赋值到状态对象，也不含 I/O / 时钟 / 裸随机 / `assert`。
   - **唯一状态变更入口是 `src/world/game.py::apply_effects`**；且它的 Effect 种类白名单只有 `flag` / `note` / `log` 三类，用 `replace` 只改 `GameState.flags` / `notes` / `log`，**`GameState.progress`（G3 门控状态）与骨架层 `World` 逐字段不动**。于是「脚本不直接改世界状态」既是结构事实，也可用 AST + 行为双重证明。成长 / 进化由 `game.train` 这条独立纯函数推进，不走脚本效果通道。

4. **存档只存三类信息，生成结果不入档且可由 seed 重建**。`SaveData(world_seed, flags, party)` frozen；`progress` / `atlas` 的语义标记全部投影成排序去重的 `flags` 字符串（带前缀），`party` 存队伍状态；`tick` / `log` / `blocked` 是运行时过程量，不持久化。序列化用 `json.dumps(sort_keys=True, ensure_ascii=False, separators=...)` 保证确定性字节；反序列化走**字段白名单 + 前缀白名单 + 类型校验**，显式抛 `SchemaError`（禁用 `assert`，抗 `python -O`），拒绝 `tiles` / `terrain_counts` / `encounter_weights` / `chunks` 等生成结果键。roundtrip 由 `tests/test_save_roundtrip.py` 落地 —— 这正是 `docs/不变量.md` #6 点名的未来符号；另用「同 seed 重跑 `generate_chunk` 逐格一致」证明不入档仍可重建。

## 被否决的备选及原因（Alternatives considered）

- **把成长刻度写进 `encounters.json` / 新增 `growth` 字段** —— 否决：需人逐次确认改受保护表 + 重建 `MANIFEST.sha256`，本次开工授权未含此项；越权改表会重演 A13 的「机器分不出人确认与 AI 自改」问题。人已明确选「代码常量 + ADR 登记」。
- **新增第四张数据表承载图鉴 / 事件脚本** —— 否决：破坏「三张表是唯一事实源」（不变量 #2），`ADR-003` 已就 NPC 否决过同类；脚本改为代码内纯数据常量，仍受 R0–R7 扫描，不形成盲区。
- **事件脚本用可执行 lambda / 回调 / `eval` 字符串** —— 否决：脚本就具备直接改世界状态的能力，「不直接改世界状态」无法机器证明，且 `eval` / 动态调用撞 R1；改为「数据 + 唯一解释器」。
- **让脚本效果能改 `Progress.region` / `abilities`** —— 否决：G3 已确立跨区域移动的唯一入口是 `progress.step`，脚本若开第二入口会形成跳关路径、破坏 ADR-003 的无跳关证明。
- **进化产出新物种 id、图鉴按编号递增** —— 否决：前者触发 R5 溯源表扩容与改表；后者违反 GDD-v0 §2「收集感来自出没条件」与术语表「图鉴 Atlas」词条。
- **存档里缓存区块 `tiles` / 遭遇权重** —— 否决：直接违反不变量 #6，且会把存档与生成器版本耦合；改为由 `world_seed` 重建。
- **重跑 `balance_check.py` / 重拍 golden 快照** —— 否决：G4 不改生成器、三表、伤害 / 捕捉公式，按 G3 先例（S3-04）无需重跑；R7 哈希保持 G1-v3 `3ab574e4…`。

## 后果（Consequences）

- 正面：全程**零改表 / 零重建 MANIFEST / 零重拍 golden 快照**；三条 DoD 都能给出机器事实（里程碑 `complete` + 死端反证、roundtrip 字节一致 + 生成结果拒绝、脚本 AST 与 `apply` 前后状态比对）；不变量 #6 从「未来符号」落地为真实证据。
- 负面 / 已知限制：**成长刻度是代码常量而非表驱动**，与项目「结构常数全部入表」的战斗数值口径不一致 —— 这是人本次明确选择的取舍，登记于此以免后续被当成疏漏「顺手改表」；**进化只是形态阶段，尚无独立造型资产**（GDD 六维自评的「原创度」差距未按 SSSSSS 补齐）；**事件脚本文案是 AI 草案，B 级品味归人复核**，不冒充已通过。
- 边界：本决定不新增、不改写 `docs/接力文件.md`「待人类裁决的问题」的任何裁决项（当前 0 项）。G3 的 S3-01（NPC 授予点由边派生）/ S3-02（分叉 / 环路拓扑未端到端实测）继续如实登记；G4 的巡图证据沿用链式拓扑，不把链式结论外推到分叉 / 环路。
- G4 交付时按 A9 产生新的里程碑裁决项（G4 是否验收通过 / 是否开工 G5）与 B 级文案品味复核，AI 不提前预支、不自判通过。
