# ADR-003：能力门与巡图的表驱动实现

> 意图层记忆：为什么这样设计。结构 AI 读代码能重建，意图只能靠人沉淀。
> 一页纸：背景 / 决定 / 被否决的备选及原因 / 后果。

## 背景（Context）

G3 要实现「表驱动解锁 + 跨区域移动 + `autoplayer.py` 跑遍拓扑与 NPC」，DoD 是「自动玩家无卡死、无跳关；每条边可达性测试绿」。

`data/topology.json` 已经有 `abilities`、7 个 `regions` 和 6 条 `edges[].requires` —— **门控条件齐备**，但**没有任何 NPC 字段**：谁授予能力、在哪里授予，表里没有写。而 ADR-001 把「剧情事件 / NPC」划归骨架层（作者意图归人），不变量 #2 / R2 又规定三张受保护表改动须人**逐次**确认并重建 `MANIFEST.sha256`。

本轮人答复「G2通过，开始下一步开发工作」只授权开工 G3，**不含**改表 / 重建清单 / 重拍 golden 快照的逐次确认；2026-11-15 早些时候那次「同意」是一次性确认，只覆盖 G2 返工。同时 R3a 要求「能力名在代码中零出现」，`tools/gate.py` 会连字符串拼接 / f-string 常量段一起折叠检查。

于是问题变成：**在不改表、不在代码里写死能力名、不新增命名资产的前提下，怎样让自动玩家既能拿到能力、又能被机器证明没有跳关或卡死？**

## 决定（Decision）

1. **门是表，代码只是解释器**。`World.from_tables()` 把 `edges[].requires` 凝固成不可变 `Edge`，`step` 只做 `requires ⊆ abilities` 集合判断；模块里不出现能力名字面量，也不调用 `has/require/unlock/can_enter` 一类带字符串参数的判断（R3a / R3b）。

2. **NPC 授予点从边机械派生，零改表**。每个区域恰好一个 NPC，标识 `npc:<region>`（用区域 id，**不另起专名**，因此不产生新的需溯源资产、不动 R5 溯源表）；对每条带非空 `requires` 的边 `u→v`，这些能力由 `u` 区域的 NPC 授予。派生规则不改写任何骨架层作者意图字段——区域命名、地标、解锁顺序仍是表里的原值，且已由人裁定沿用（A10）。

   > 以当前表为例：r2 的 NPC 授予 r2→r3 所需能力，r4 授予 r4→r5，r5 授予 r5→r6，r6 授予 r6→r7；与 GDD-v0 §3「道馆 / 试炼 / 补给站给能力」的叙事一致。

3. **有向边 + 受限反向**。沿 `u→v` 正向走必须 `requires ⊆ abilities`；沿 `v→u` 反向只允许回到**已访问**区域。反向不会把玩家送进尚未解锁的区域，因此跳关路径被结构性堵死。跨区域移动全部走 `step(state, "edge:<i>", world)`，没有第二条路径改 `region`。

4. **自动玩家确定性、无随机**。动作按表序选择（巡查 → NPC → 未访问且开放的正向边 → 在已访问子图上 BFS 回退），不用 `random` / 时钟，符合不变量 #1。区块地形仍由 G1 的 `rng(world_seed, region, cx, cy)` 生成，因此**拓扑轨迹与世界种子解耦**：换种子只变地形摘要，不变解锁顺序。

5. **状态转移沿用 G2 的纯函数形态**：`step(state, action, world) -> state'`，`World` / `Progress` 均 frozen，用 `dataclasses.replace` 返回新对象；受阻不抛异常也不静默，写成 `blocked` 事件。`coverage()` 用「能力闭包 + BFS」静态证明全区域可达，自动玩家的运行轨迹则是动态反证。

## 被否决的备选及原因（Alternatives considered）

- **在 `topology.json` 新增 `npcs` / `grants` 字段** —— 否决：需人逐次确认改受保护表 + 重建 `MANIFEST.sha256`，本轮未获授权；且 NPC 位置属骨架层作者意图，AI 不得借开工之名自行扩张设定。留作人日后显式裁定的选项。
- **在代码里写 `NPC_GRANTS = {"r2": "surf"}` 之类映射** —— 否决：能力名字面量直接撞 R3a，门控重新散落到代码里，正是 ADR-001 明确否决的形态。
- **允许反向自由通行** —— 否决：在有分叉的拓扑上，可能从深处反向进入尚未解锁的区域，形成绕过门控的跳关路径；「反向只回已访问」是最小且可机器判定的限制。
- **自动玩家随机游走直到全图覆盖** —— 否决：违反不变量 #1、不可复现，且「无卡死」无法给出有限步证明；改为确定性的表序遍历 + BFS 回退。
- **访问区域即自动获得全部能力** —— 否决：门控形同虚设，无跳关测试会假绿；能力必须来自 NPC 交互这一显式动作。
- **新增第四张数据表承载 NPC** —— 否决：破坏「三张表是唯一事实源」（不变量 #2），也绕开了 R2 的保护意图。

## 后果（Consequences）

- 正面：全程**零改表 / 零重建 MANIFEST / 零重拍 golden 快照**，R7 哈希保持 `3ab574e4…`；门控只有一个事实源；「无跳关」可按事件逐条机器核对；「无卡死」由静态 `coverage()` 与动态轨迹双证据支撑。
- 负面 / 已知限制：**NPC 授予点是从边派生的实现约定，不是表内显式作者设定**；一旦未来出现「同一区域 NPC 授予多个能力」「一条边要求多个能力」「分叉 / 环路拓扑」，派生规则仍可用但须重新核对 `coverage()` 输出，不能默认沿用当前链式直觉。
- 边界：本决定不新增、不改写 `docs/接力文件.md`「待人类裁决的问题」中的任何裁决项。若人希望把 NPC 与能力来源写成表内显式设定，须**另开裁决**并逐次确认改受保护表，之后再落新 ADR；AI 不自行推进。
- G2 遗留（**G3 实施时点的记录**）：S2-03 满血捕捉率、A11 手感定稿当时仍归人，故本 ADR 不触碰战斗 / 捕捉公式与 `docs/平衡采样报告.md`。**后续（2026-11-15 22:02）**：人裁决 S2-03「采纳」、A11「先定稿」→ 由 G2 遗留返工按 `ADR-002` §5 / §8 实施并同步采样报告；这是 G3 验收通过之后的独立返工，不改写本 ADR 的 G3 实施边界。
