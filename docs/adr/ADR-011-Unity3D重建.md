# ADR-011：Unity 3D 可玩独立原型重建（G9）

> 意图层记忆。本 ADR 显式 supersede `ADR-009` 的 2D 开放世界引擎口径与 `ADR-001` §被否决「3D 实时世界」——该否决由人在 2026-11-27 以 P1「C，我是希望能是3D的」推翻。

## 背景（Context）

G0–G8 在 Python + pygame 上完成了规则密集的验证原型：268 用例全绿、确定性 / 表驱动门控 / 存档 / 战斗 / 捕捉 / 连续世界均有机器证据。但人在 2026-11-27 连续三轮反馈后明确裁决：**「验收不通过，因为游戏需要大改甚至是重建」**（P2），并选择 C 路线 **Unity 全量重建 + 3D**（P1），档位上调为 **可玩独立原型**（P3）。

诊断结论（`docs/提案-PokeWorld体验升级建设方案.md`）：画面 "不会动" 的根因是 `overworld_view.py:284` 阻塞式 `event.wait()` 无渲染帧钟、全 src 无音频 / 动画状态机；操作感根因是离散整格移动 + 遭遇阈值 0.18（期望 5.56 步一场）；制度根因是四道门从未验"好不好玩"。这些在 2D Python 框架内属可补但天花板低，人据此选择换引擎 + 3D。

## 决定（Decision）

1. **引擎与维度**：新工程用 Unity，目标 3D；具体 Unity 版本 / 包版本**不臆造**，取人本机环境或 Hub 新建工程，未核验前标注"待核验"。
2. **可玩独立原型定位**：档位从 A4「原型级」上调；以"画面感 + 操作感兼备、可独立运行体验"为收口，不再以纯机器可判定 DoD 为唯一标准；新增第五道门「体验门」（机器测 fps / 响应帧数 / 演出覆盖，真人试玩 ≥10 分钟签核）。
3. **旧工程冻结归档**：G0–G8 的 Python 工程整体保留，三张 `data/*.json` / `MANIFEST.sha256` / `tests/golden_seed.json` 与 268 用例保持原样全绿，**不删、不改、不迁移**。AI 对 P4 的合理决断即"新工程独立数据资产、旧受保护数据零触碰"。
4. **设计先冻结后施工**：阶段一产出 15 章策划案 + 带编号冻结清单并置 `frozen`；工程侧每个实现文件写 `// @trace 编号`，自检脚本统计覆盖率。未冻结不进工程阶段（专家硬门禁）。
5. **手绘美术方向**：风格锚点 = 手绘（人 P5 给定）；色板色号 / 比例 / 单图尺寸 / 资源规格由 AI 在冻结清单 `ART-*` 条目内定稿；资产原创 + 逐项溯源登记，禁用第三方 IP（不变量 #7 精神延续）。
6. **不手写场景 / 预制体 YAML**：用 Editor 脚本或运行时程序化构建生成场景，并确保进入构建列表（防黑屏无声失败）。
7. **验收另裁**：G9 交付后按 A9 另立人裁决项；AI 不自判通过。G8 的"验收不通过"是独立裁决，不自动转为 G9 通过。

## 被否决的备选及原因（Alternatives considered）

- **A：pygame 深度强化** —— 人 P1 明确选 C；3D 需求在 pygame 内不可达。
- **B：Godot 4 + Python 内核** —— 人 P1 明确选 C，不是 Godot。
- **在旧 Python 工程上改表 / 重拍快照来实现 3D** —— 否决：改表须逐次人确认，且 3D 需换引擎，旧工程继续当规则验证库更有价值。
- **臆造 Unity 版本号填进工程** —— 否决：包解析失败风险高；专家规则"不猜版本"，宁可标待核验。

## 后果（Consequences）

- 正面：3D 与引擎级动画 / 音频 / UI 可落地；旧工程零风险归档；设计冻结 + 引用标记让"是否照策划案做"机器可查。
- 负面：本机无 Unity，本轮无法真实编译 / 进播放模式，所有运行结论均待验；重建成本高，G0–G8 的机器证据不自动继承到新工程；Unity 版本未核验前工程骨架需人补一步。
- 后续注意：任何需求变更必须改冻结清单并递增 `version`；编号不得复用；G9 验收与 G8 验收分开落单。
