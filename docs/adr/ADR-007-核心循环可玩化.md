# ADR-007：核心循环可玩化 —— 战斗 / 捕捉接进会话与窗口

> 意图层记忆：为什么这样设计。一页纸：背景 / 决定 / 被否决的备选及原因 / 后果。
> 状态：**G7 已实施完毕（2026-11-17），按 A9 待人裁决验收**；逐条机器证据以 `docs/工单/G7-核心循环可玩化.md` 为准。**AI 未自判 G7 通过、未做独立冷眼、未写 G8 代码。**

## 背景（Context）

G6 冷眼 F-01 与 `docs/GDD-v0.md` §8 完整度 4/6 都指向同一缺口：`g5_report` 的 20 步通关序列只含 `survey` / `npc` / `edge:i`，**战斗 / 捕捉只有 G2 纯函数与采样证据，没有端到端在窗口里玩过一遍**。2026-11-17 人裁决「G6验收通过，开发G7」并选项确认方向「核心循环可玩化」，授权把 G2 已验收的战斗 / 捕捉接进 G5 窗口，复用 A11 已定稿数值与三表。

约束：授权**不含**改受保护三表 / 重建 `MANIFEST.sha256` / 重拍 golden 的逐次确认 → 必须零改表实现。既有资产已具备全部要素：

- G2 `src/battle/{state,engine,context,rules}.py`：frozen 状态机 `step(state, action, rng)`，action 全集 `encounter / attack / catch / flee / item:<id>`，`outcome ∈ {idle, active, won, caught, lost, fled}`，全部数值来自 `encounters.json`（`state.py:44-65` L53 `Rules.from_tables`；`engine.py:72-157`）。
- G1 `src/gen/chunk.py::generate_chunk`：`encounter_weights[phase][cid]`（L80–85）可直接作遭遇权重，无需新表。
- G4 `src/world/atlas.py::observe`（L56–65）+ `game.py::observe`（L106–110）：图鉴登记已有唯一入口。
- G5 `src/world/session.py::apply`（L161–192）是唯一状态转移、`src/view/layout.py::frame_of`（L91–110）是纯投影、`window.py::run_window`（L74–135）键盘 → 动作、CLI 动作走注入 handler。

## 决定（Decision）

1. **战斗 / 捕捉编排进 `Session.apply`，不新建战斗服务层**。`Session` 增 frozen 运行时字段（战斗状态 + 对应 `RngContext` + 待落地遭遇 cid）；`apply` 扩展 action 分发 `encounter / attack / catch / flee / item:<id>`，每条都转调 `src/battle::step` 并在成功后 `ctx.advance()`（engine 硬校验 `rng.tick == state.tick`，`engine.py:76-77`）。遭遇时由 `generate_chunk(... )["encounter_weights"][session.phase]` 取权重、`state.party[0].cid` 取 ally、既有 `items` 键取背包——**全部来自既有表，零字面量数值**。

2. **战斗终局经既有入口落地，不另开图鉴写入口**。`caught / won` 的物种经 `game.observe(state, cid, region, terrain, phase)` 进入图鉴；`lost / fled` 记日志并回探索态；六种 `outcome` 全部分支处理，终局清空战斗运行时字段。战斗运行时**不进存档**（`SAVE_KEYS` 三类不变），读档后战斗重置，作为新限制如实登记。

3. **表现层只读投影，不新增 I/O handler**。`Frame` 增战斗投影字段（双方 hp / status / 装备球 / outcome / 日志尾），`frame_of` 仍纯函数；`draw` 按 `Frame` 画战斗面板；战斗键经 `action_for_key` 映射后走 `run_window` 的 `apply` 纯转移分支（现有 L112–122 已区分 CLI handler 与纯转移，战斗动作属后者）。文件 I/O 仍只在 `src/main.py`。

4. **端到端报告 `tools/g7_report.py` 复用 G5 / G4 模板**。`run()` 纯函数 + `deepcopy` 零改表 + 反证（空权重不遭遇 / 非法动作抛错 / 终局未清战斗态）+ `complete` 多条件合取（含通关、图鉴、存档 roundtrip、纯投影、依赖可用、表 / manifest / golden / gate 未变），`main()` 只做 I/O、按 `complete` 决定 exit 0/1。

5. **全程零改表 / 零重建清单 / 零重拍快照**。A11 数值不动、`balance_check.py` 不重跑（`G2-balance-v3` 不变）；新增 `src/battle/ui/` 之类子目录仍在已登记 `SCAN_DIRS=("src","tools")` 内（gate L23、L316–321），不改 R6；R3a 能力名字面量零出现（含新增 UI 文案 / 日志 / docstring）；R1 不引时钟 / 裸随机。

## 被否决的备选及原因（Alternatives considered）

- **改三表扩充潮灵 / 调平衡顺便做掉** —— 否决：授权不含改表逐次确认（S6-02 挂起），与不变量 #2 冲突。
- **另建 `src/battle/ui/` 独立战斗服务层持有自己的状态** —— 否决：会形成第二个状态入口，破坏「`apply` 唯一状态转移」与不变量 #4 单向数据流；改为编排进 `Session.apply`。
- **战斗状态写进存档让读档续战** —— 否决：`SAVE_KEYS` 三类字段是不变量 #6 的硬约束，写生成 / 战斗运行时状态会破坏投影原则；如实登记为读档重置限制。
- **战斗动画引入帧钟 / `time` 驱动** —— 否决：R1 禁时钟，沿用事件驱动；观感属 B 级归人。
- **`complete` 直接写 `True` 或单点判定** —— 否决：G0 冷眼「证明方法失真」教训，多条件合取 + 反证才可信。

## 后果（Consequences）

- 正面：首次把收集游戏的核心动作（遭遇 / 战斗 / 捕捉）在窗口里端到端玩通，补齐 `GDD-v0.md` §8「完整度」维最大差距；G2 纯函数、G1 生成器、G4 图鉴、G5 窗口全部复用不改；零改表零重拍。
- 负面 / 已知限制：战斗运行时不进存档（读档后战斗重置，与 S4-02 / S5-02 同类）；本设计只对当前链式拓扑与现有 8 潮灵成立，不外推到分叉 / 环路（S3-02 / S5-03）；窗口战斗观感与新增文案属 B 级、归人复核，不冒充已定稿；AI 不自判验收。
- 边界：G3 S3-01/S3-02、G4 S4-01~S4-05、G5 S5-01~S5-07、G6 S6-01~S6-03 继续如实登记；不实施 8 潮灵扩充 / 平衡调优。
- G7 交付时按 A9 产生新的里程碑裁决项（G7 是否验收 / 是否开工 G8 / B 组遗留），由人裁决，AI 不自判、不预支结论。

## 实施结论（2026-11-17 · 实现者登记，非独立冷眼）

- 五项决定全部落地：战斗编排住进 `Session.apply`（未开第二状态入口）；终局经 `game.observe` 回写图鉴；表现层只读 `Frame` 增战斗面板；`tools/g7_report.py` 复用 G5/G4 模板、多条件合取 + 三类反证；全程零改表 / 零重建清单 / 零重拍快照。
- 机器事实：`g7_report.py G7-a` → `complete=true`（空册捕获 c01 入图鉴、终局清态、存档 roundtrip、帧纯投影、门控三绿）；`G7-demo` 战败种子 → `complete=false`（反证合取非恒定真）；四道门 233 → **253 用例**全绿；依赖缺失态 `skipped=13` 仍全绿；`git diff` 表与快照 0 行。
- 新增已知限制 S7-01（战斗运行时不进存档，读档重置）/ S7-02（无独立潮灵美术、观感归人）/ S7-03（固定捕捉策略只覆盖链式拓扑起始区域），照登不抹去。
- 自审非冷眼：G7 未做独立会话评审（冷眼按人裁定维持 G6，且 S6-01 无第二次复评）；**不自判验收通过**。
