## 架构概览

三层结构（决策理由见 `docs/adr/ADR-001-固定骨架与种子生成分层.md`）：

```
A 骨架层（人工定 · 受保护）   data/topology.json / species.json / encounters.json
        │  只读加载（src/schema.py）
B 血肉层（种子生成 · 纯函数） src/gen/      rng(world_seed, region_id, cx, cy)
        │  由能力门挂到进度
C 门控层（表驱动 · 不散落）   topology.json 的 edges[].requires
        │
D 表现层（G5 才引入）         pygame 渲染 / 输入 / 存档
```

数据流单向：骨架表 → 生成器 → 区块 → 遭遇 / 战斗纯函数 → 状态；表现层只读状态，不回写世界。

## 黄金路径 / 参考实现（照着它新增，质量最高）

- **`src/schema.py`**：数据契约的参考实现——`must()` 显式抛错、无 `assert`、无 I/O 副作用、无全局可变状态。
- **`tools/gate.py`**：「会说话的墙」参考实现——AST 检查、归一化、扫描根登记、错误三要素；新增规则须同步补故意违规用例。
- **`tests/test_optimize_mode.py`**：优化模式回归的参考实现——在真实子进程里复现 `-O`，而非只测纯函数。
- 低委托铸好参考实现，后续同构模块高委托照抄。

## 关键流程入口

- 测试入口：`python tools/verify_all.py`（第 0 道自检 + 四门全绿）；独立跑 `python -m unittest discover -s tests -v`。
- 静态规则单看：`python tools/gate.py`。
- 验证入口（DoD 怎么证明）：各工单「出（验收）」栏逐条附命令与测试名。
- 契约测试：`tests/test_schema.py`；规则门测试：`tests/test_gate_rules.py`；golden seed 快照 G1 起。
