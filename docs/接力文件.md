## 踩坑与已试过且失败的方法

- ❌ 在 `WorkBuddy/宝游` 初始化空 git 仓库 → 用户随后指定 `Desktop/PokeWorld` 为唯一工作目录；该临时目录无文件，残留空 `.git` 与两个空目录，待用户决定是否清理。
- ❌ 数据校验写成 `assert` → `python -O` 剥离全部校验，四门假绿（F-16）。已改 `schema.must()` 显式抛错 + 第 0 道自检。
- ❌ 规则门用 AST 节点名精确匹配 → 动态导入 / 属性链 / 拼接漏检（F-15）。已加固到 14 个回归样例。
- ❌ `ast.literal_eval` 折叠字符串相加 → 拒绝字符串 `+`（防 DoS）。改为自写 `_fold()` 递归折叠。
- ❌ R5 用「GDD 全文子串包含」核对溯源 → 正文任意位置写名字即可伪造（R-03）。改为正则逐行解析并比对名称。
- ❌ 用 `git diff --stat` 证明「≤5 文件 / ≤400 行」→ untracked 零统计（F-03）。改用 `git add` + `git diff --cached --shortstat`，并拆成 C1–C14 小笔。
- ❌ 四道门直接 discover 含「会再启动 verify_all」的测试 → 无限递归。加 `POKEWORLD_GATE_CHILD` 守卫只 skip 那 2 例，并由第 0 道自检等价覆盖。
- ❌ `DYNAMIC_EVAL` 用裸子串匹配 → `getattr(cfg,"import_path")` 误报（N-01）；改成只检测内建调用后，又因 `re.compile(正则字面量)` **自撞墙**。最终改为「完整词正则 + 仅 `ast.Name` 内建调用」。
- ⚠️ 本机代理 `http://127.0.0.1:1637` 对 `github.com` 返回 502，`api.github.com` 却通；**推送必须 `env -u HTTPS_PROXY -u https_proxy -u HTTP_PROXY -u http_proxy -u ALL_PROXY git push origin main`**。
