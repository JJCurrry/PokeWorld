## 踩坑与已试过且失败的方法

### G1 新增

- ❌ 用 `random.*` / `numpy.random` / `time` 或 Python 内置 `hash()` 生成 → 不可复现（内置 hash 有进程随机化），golden seed 快照失效。改用 `hashlib.blake2b` 对 `world_seed|region|cx|cy|stream|index` 派生。
- ⚠️ `src/gen/` 模块级放可变 dict（地形编码表）会撞模块级不变量「禁止写模块级可变状态」→ 改为不可变 tuple 常量，映射字典在函数内临时构造。
- ⚠️ R3a「能力名零出现」连 **docstring 的字符串常量**都算（`gate.collect_strings` 收集所有 `ast.Constant`）；G1 代码全程避开 `surf` / `rock_smash` / `strength` / `league_pass` 等词。
- ⚠️ Git 在 Windows 检出可能把 LF 转 CRLF，直接按字节算哈希会误报快照被改 → R7 先做 `\r\n → \n` 行尾归一化再算 SHA256。
- ⚠️ **R7 拦得住「改快照」，拦不住「同时改 `gate.GOLDEN_SNAPSHOT_SHA256`」**（自审 S-01）：这是制度性约束，不是密码学约束，机器无法区分人确认与 AI 自行同步。别声称「已机器强制」。
- ⚠️ `encounter_weights` 的因子含 `base_catch`，值落在 0~1 但不是概率（自审 S-02）；术语表已立词条，G2 消费前须归一化并确认口径。
- ⚠️ 端到端规则门用例的临时仓库若不复制 `tests/golden_seed.json`，R7 会让 15 个既有用例全撞「快照缺失」；`setUp` 已补复制，`test_tests_dir_is_not_production_scanned` 的 `mkdir()` 同步改 `exist_ok=True`。
