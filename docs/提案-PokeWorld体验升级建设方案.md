# PokeWorld 体验升级建设方案（提案 v1）

> **状态：提案，未获开工授权。** 本文件只做分析与方案，不改任何代码、不改三张受保护表 / MANIFEST / golden 快照、不改三处裁决清单（接力文件 / G8 工单 / 待裁定项）。
> 提出时间：2026-11-27。触发：人反馈「非常没有可玩性，非常草率」+「我需要画面感和操作感兼备的游戏」。
> 规则遵循：`CLAUDE.md` 原则 1/3/5、A9（验收与授权开工是两件事）；银橙AI 六段输出骨架。

## S1 结论摘要

1. **人的判断成立，且不是"没做够"，是"标准里没有这一项"。** 项目四道门 268 用例全绿，但没有任何一条验「好不好玩、看不看得动、按不按得动」；`docs/任务架构细分.md:61` A4 明确「目标档位 = 原型级」，`docs/GDD-v0.md` §8 自评最低 1/6、性能 2/6。门绿与可玩性之间是制度性断裂，不是某几个 bug。
2. **画面感的硬伤是"不会动"而非"不好看"。** `src/view/overworld_view.py:284` 用 `pygame.event.wait()` 阻塞事件循环，全 `src/` 无 `Clock` / `tick(`、无 `mixer` / `Sound` / `.play(`。源码里所谓动画（水波纹、踏步、地标脉冲）由帧计数驱动，而帧只在按键时推进——不按键画面就是静帧。
3. **操作感的硬伤是"反馈维度太少"。** `src/world/explore.py:134-154` 每次移动瞬间跳 1 整格（30 px）、无插值无实体碰撞；遭遇阈值 `0.18`（`:25`）意味着几何分布期望约 **5.56 步就强制进一次战斗**；战斗表现只是侧栏两行文字 + 一张静态图。
4. **机器证据与人体验长期脱节。** `tools/ow_report.py` 靠 `explore.autoplay` 直接发动作，绕过窗口键位链；直到 D100（`569581d`）才补上真人按键路径的三处断链。这说明"验证全绿"不能替代"人玩得动"。
5. **建议动作**：先立体验标准（阶段 0），再做"动起来 + 按得动"（阶段 1），再做氛围（阶段 2），最后填玩法厚度（阶段 3）。**引擎路线必须先由人裁决**，本提案给出 A/B/C 三条路线与推荐，不擅自开工。

## S4 判断或计算链条（可复算）

**① 遭遇节奏（可复算，不是手感描述）**

- 触发值 `u = rng(seed,"explore",int(x),int(y)).unit()`（`explore.py:153`），触发条件 `u < 0.18`（`:25` `:184`）。
- 每格独立确定、阈值恒定 → 服从几何分布，期望步数 `E = 1/p = 1/0.18 ≈ 5.56` 步/场。
- 按 `TILE=30px`，相当于约每 `5.56 × 30 ≈ 167 px` 强制中断一次探索。
- 若阈值改 0.05 → `E = 20` 步 ≈ 600 px；若改"可见野外精灵 + 主动接触"，期望由玩家控制。**当前数值可用源码直接复算，不是估计。**

**② 帧与动画（口径区分）**

- `block=True` 时循环靠 `pygame.event.wait()` 唤醒，无输入期间画面重绘次数 = 0；`block=False`（smoke 测试）才靠 `pygame.event.get()` 连续推进。
- 因此"水波纹周期 8 帧"在真人游玩时等于"8 次按键"，不是时间周期。
- 目标 60 fps → 帧间隔 16.7 ms；若插值 150 ms，约 9 帧完成一格移动。**目标值属【假设 H2】，须实测校准。**

**③ 质量门覆盖缺口**

- 268 用例的证据字段是 `complete / roundtrip / pure / frame_pure / manifest_ok / golden_snapshot_ok / art.available` 等，均为**状态与合规事实**。
- G5/G7/G8 窗口用例（含 `test_g5_view.py` 假 KEYDOWN）验的是"能画、能收到键、投影数据正确"，不验动画连续性、音效、打击感、目标感。
- 结论：**体验门缺失是制度性缺口，换引擎本身不会自动补上它。** 这是本方案把"阶段 0 立标准"放在第一位的原因。

## S5 实操动作：路线对比与分阶段建设

### 5.1 引擎 / 技术路线对比（人裁决项，AI 不代选）

| 维度 | A · pygame 深度强化（保留现有架构） | B · Godot 4 + Python 规则内核保留 | C · Unity 全量重建 |
|---|---|---|---|
| 画面上限 | 中（2D 手绘 / 像素可做到流畅精致） | 高（原生 AnimationPlayer / Tween / 粒子 / 光照 / UI） | 高（2D/3D 皆可、生态最大） |
| 操作感上限 | 中（插值 / 输入缓冲 / 震屏需手写） | 高（InputMap / 动画状态机现成） | 高（Input System / Animator / Cinemachine） |
| 268 用例 + R0–R7 门禁 | **完整保留** | 可保留（Python 侧独立跑门禁） | 需重写规则层与测试体系 |
| 三表 / golden / 不变量 | 零改 | 零改（表现层与规则层分离） | 需重建等价机制 |
| 16 件原创 PNG | 直接复用 | 可复用 | 可复用 |
| 成本 / 主要风险 | 低；天花板有限、手写动画代码量大 | 中；需定义表现层 ↔ 规则层协议 | 高；丢门禁资产，且 `ADR-001:30` 的"动画状态机是 AI 弱项"风险回归 |
| 适合 | 自用、快速让人看到变化 | 像样的独立 2D 游戏 | 3D / 多平台 / 商业发布 |

**AI 的推荐（不替代人裁决）**：先做 **A** 的阶段 1–2 快速消除"不动画、没声音、瞬移、战斗无演出"四类可感知问题；是否转向 **B** 在阶段 2 结束时凭试玩结果裁决；**C** 仅在人明确要 3D / 商业化 / 多平台时选。理由：项目的核心价值是"纯函数规则内核 + 可机器复核的门禁"，C 会把它清零；而 ADR-001 否决 3D 的理由至今未被推翻（G8 只推翻了"无缝否决"）。

### 5.2 分阶段路线（每阶段独立验收，不跨步）

**阶段 0 · 体验规格与可玩性门（立标准，不写玩法代码）**
- 产出：体验规格书（画面锚点 / 手感参数 / 节奏指标）、可玩性 DoD、**设计冻结清单 v1**、第五道门规则提案。
- 每条指标写「当前值（源码实测）→ 目标值【假设 H2】→ 测量方法」。
- 人验收点：确认画面风格锚点、手感参数、目标档位（A4 是否上调）。

**阶段 1 · 动起来（画面与操作骨架，按路线 A 写细节）**
- 表现层引入渲染帧钟与连续重绘（**不进状态层、不进 RNG**；`R1` 禁 `import time`，须用已登记模块的掌握方式，落规则前先跑门禁验证）。
- 移动插值：1 格 30 px / 120–180 ms 缓动；4 向行走序列帧；地标 / 树木 / 水域的实体碰撞与软反馈。
- 相机平滑跟随；输入缓冲与连击；每次按键的视听反馈（轻震 / 粒子 / SFX 占位）。
- 战斗演出链：转场 → 前摇 → 命中 → 伤害飘字 → 血条变化 → 捕捉光效 → 结算。
- DoD：60 fps 连续重绘（机器测）；按键到反馈 ≤1 帧（机器测）；无穿模（机器测）；演出事件序列完整（日志断言 + 人眼确认）。
- 硬约束：268 用例全绿、零改三表 / 清单 / golden。

**阶段 2 · 有氛围（画面感）**
- 音频总线：区域 BGM + 脚步 / 遭遇 / 攻击 / 捕捉 / UI 音效 + 昼夜环境音（须原创或授权，全程登记 GDD §6）。
- 昼夜光照渐变（当前只是 `phase` 文本标签）、天气 / 水面 / 落叶粒子、地标灯光。
- UI 重做：HUD、图鉴界面、道具栏、任务指引、独立战斗界面（替代侧栏文字）。
- DoD：≥3 套区域氛围；战斗有视听高潮；UI 验收截图归档；人眼确认后由人裁决。

**阶段 3 · 有玩法厚度（可玩性；须先获改表授权）**
- 目标层次：主线（到 r7）+ 支线（图鉴收集给实际回报）+ 短期（遭遇 / 道具 / 每日种子）。
- 遭遇节奏按 S4① 重调；成长可见化（等级 / 技能 / 进化）；失败与资源（HP 恢复、道具经济、温和惩罚）；内容扩充（潮灵数量 / 分叉环路）。
- DoD：真人 10 分钟试玩记录；首次捕获 ≤3 分钟【H2】；至少 2 条并行追求线；分叉 / 环路端到端实测（闭合 S3-02 / S8-02）。

**阶段 4 · 性能与发布收口**
- 帧率 / 包体 / 内存阈值（GDD §8 性能 2/6 当前无验收值）；exe 重建；真人试玩签核；体验门全勾。

### 5.3 第五道门：体验门（Playability Gate）

| 层 | 测什么 | 产物 | 能否替代人 |
|---|---|---|---|
| 机器可测 | fps、按键到反馈帧数、演出事件覆盖率、遭遇间隔分布、穿模计数、音频事件触发数 | `tools/playability_report.py` JSON，进 `verify_all.py` | 否，只固化可观测事实 |
| 人可判定 | 想不想继续玩、知不知道下一步做什么、画面是否舒服、手感是否跟手 | 真人试玩记录（≥10 分钟）归档工单 | **是，只有人能签** |

> 设计目的：堵住 D100 暴露的那类盲区（状态机全绿但真人按键无反应）。体验门**不是**品味裁决，也不把 AI 自审冒充冷眼。
