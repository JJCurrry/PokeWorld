## 设计要点（意图层，防后续被改坏）

- **门控唯一事实源是 `edges[].requires`**：代码不写死能力名，也不写 `has/require/unlock/can_enter` 类带字符串参数的调用（R3a / R3b）。表怎么改，门就怎么变。
- **NPC 授予点由边机械派生，不改表**：每个区域一个 NPC（标识 `npc:<region>`，无专名、不新增需溯源资产）；一条边 `u→v` 的 `requires` 由 `u` 区域 NPC 授予。这不新增 / 不改写任何骨架层作者意图字段（区域命名、地标、解锁顺序仍由人定）。
- **有向边 + 受限反向**：正向按 `requires ⊆ abilities` 判定；反向只允许回到**已访问**区域，杜绝「从深处反向绕进未解锁区域」的跳关路径。
- **自动玩家无随机**：决策按表序确定性推进，不引入 `random` / 时钟；区块地形仍由 G1 的 `rng(world_seed, region, cx, cy)` 生成，拓扑轨迹与种子解耦。
- **状态转移沿用 G2 纯函数风格**：`step(state, action, world) -> state'`，`World` 与 `Progress` 都 frozen，`replace` 返回新对象；受阻不抛异常也不静默，记为 `blocked` 事件，便于机器核对。
- **零改表 = 零快照风险**：`autoplayer` 只调用既有 `generate_chunk`，不改生成器、不重拍 golden 快照（R7 哈希保持 `3ab574e4…`）。
